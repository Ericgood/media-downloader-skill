## 1. 选择标准

- 优先仍在维护、许可证清晰、可以自托管或本地运行的项目。
- 真实下载优先于 README 宣称的支持列表。
- 不把 GPL/AGPL 项目源码复制进 MIT 仓库；通过独立 CLI 或公开 API 连接。
- 单一项目失效时保留失败证据并切换独立实现。
- 默认链路不读取浏览器 Cookie，不绕过访问控制。

## 3. 实测后作出的取舍

### TikTok

安装的最新 `yt-dlp 2026.07.04` 对两条当期公开 URL 都返回 `Unexpected response from webpage request`。因此它仍保留为首选，但不能作为唯一方案。公共 TikWM 兼容端点真实下载成功；Cobalt 作为用户可控的开源自托管第三层。TikWM 是托管服务，不宣称为开源依赖，文档明确其数据边界和替换方式。

### 抖音

`yt-dlp` 对当期公开视频要求新鲜 Cookie。直接请求桌面完整页没有可解析数据，但把视频 ID 转换为官方 `iesdouyin.com/share/video/{id}` 后会返回 `_ROUTER_DATA`，真实下载成功且不使用 Cookie。因此 v0.1.0 选择轻量本地解析为默认第二层，不引入大型抓取器的 Cookie 与浏览器依赖。

### X/Twitter

测试帖在 yt-dlp 中报告找不到视频，FxTwitter/FxEmbed API 返回可下载 MP4，最终文件通过 `ffprobe`。这说明独立后端确实覆盖了主引擎盲点。

### Bilibili

匿名低清格式由 yt-dlp 成功获取；Cobalt 保留为可配置 fallback。没有为了高分辨率静默读取 Cookie。

### Suno 与 Udio

两者都从公开页面中定位实际歌曲对象，再下载源站 CDN 资产。解析器不使用页面全局第一个 `title`/`artist`，避免拿到应用壳层元数据。音频、封面、歌词和 JSON 元数据均完成真实验证。

## 4. 后续维护触发条件

- 某平台连续两次 live validation 失败：建立 issue，保留 HTML/JSON 的脱敏最小 fixture，评估替代项目。
- 主后端 30 天无维护且已有兼容性故障：降低优先级或移除。
- 托管服务出现隐私、可用性或限流问题：优先迁移到自托管 Cobalt 或新的许可证清晰项目。
- 每次发布必须重新跑受影响平台的真实下载；仅更新解析 fixture 不足以发布支持声明。
